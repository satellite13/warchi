# Политика безопасности

## Поддерживаемые версии

Исправления безопасности сейчас предоставляются на best-effort основе для актуального состояния ветки `master`.

## Как сообщить об уязвимости

Пожалуйста, **не** публикуйте уязвимости в открытых issue.

Передайте отчёт мейнтейнерам по приватному каналу и включите:

- описание уязвимости
- влияние/риск
- шаги воспроизведения
- возможную стратегию исправления

Если приватный канал ещё не определён, создайте его перед публичным релизом и обновите этот файл.

## Целевые сроки реакции (best effort)

- Первичное подтверждение: до 5 рабочих дней
- Триаж и оценка влияния: до 10 рабочих дней
- Срок исправления: зависит от критичности и сложности

## Рекомендации для безопасного деплоя

- Используйте production-безопасные значения для API и auth-конфигурации
- Держите backend-сервисы в доверенных сетевых границах
- Используйте HTTPS на ingress/load balancer уровне
- Не коммитьте секреты в `.env` и Helm values
- Регулярно обновляйте зависимости и базовые образы
