# Availability guard verification

Проверка подтверждает, что UI корректно переходит в глобальный блокирующий режим, когда backend или сервис авторизации недоступен.

## Быстрый автоматический запуск

Из корня `warchi`:

```bash
npm run verify:availability
```

Скрипт `scripts/verify-availability-guard.sh` проверяет:
- проводку outage-сигналов в `src/api/apiClient.ts`;
- наличие глобального блокера в `src/App.vue`;
- наличие i18n-ключей outage-сообщений;
- успешную сборку фронта.

## Ручной smoke-check

1. Запустить frontend (`npm run dev`) с backend, который отвечает `502/503/504` или недоступен.
2. Выполнить защищенное действие (например, загрузка моделей/нотаций).
3. Убедиться, что появился глобальный блокер с причиной недоступности.
4. Восстановить backend.
5. Проверить, что блокер снимается автоматически (auto-retry).

Отдельно проверить authz-кейс:

1. Вернуть backend, но сломать доступность Cerbos.
2. Вызвать endpoint, который проходит авторизацию через Cerbos.
3. Убедиться, что UI показывает authz outage-сообщение.
