# Версионирование нотации: компоненты и связи

## Решение: копия с новыми версиями

При создании новой версии нотации — **копировать** все компоненты и связи в новую нотацию и выставлять им **version = version новой нотации**. Старая нотация (и её компоненты/связи) остаётся без изменений — диаграммы на ней продолжают работать. Новая версия нотации = цельный срез с согласованными версиями.

## Как сейчас

- **Компоненты и связи** привязаны к нотации по **id нотации** (FK). Уникальность: `(notation, name, version)`. Версия хранится в поле `version` (тип `version_type`).
- **RelationRules** не имеют своего `version`, привязаны к Relations; при копировании нотации копируются вместе со связями. Обязательно перемаппить `fromComponent` и `toComponent` на новые id компонентов (по маппингу старых id → новых).
- **Новая версия нотации** возможна двумя путями:
  1. **PUT /api/v1/notations/{id}** — меняется версия **в той же записи** (тот же id). Все компоненты/связи остаются привязаны к этому id, их версии не трогаются.
  2. **POST /api/v1/notations/{sourceId}/copy** — создаётся **новая запись** нотации, копируются компоненты, связи и relation rules. У копий выставляется `version = newNotation.version`.

## Что нужно реализовать

### 1. copyNotation: поднимать версии при копировании — ✅ сделано

В **NotationsController.kt**, метод `copyNotation`: при копировании Components и Relations выставляется `version = newNotation.version`. RelationRules: перемаппинг `fromComponent`/`toComponent` (уже делается через `componentIdMap`).

### 2. Подсветка при редактировании диаграммы — ✅ сделано

При редактировании диаграммы, если для используемой нотации есть **новая версия** (найдена по `notations.source_id = currentNotationId`), показывается баннер: «Есть новая версия нотации (name version). Можно перейти». API: `GET /api/v1/notations/{id}/newer-versions`.

### 3. Переход на новую версию нотации

При переходе диаграммы на новую версию (миграция) — перемаппинг componentId/relationId в `attrs`, смена `notationId`. Подробности: [diagram-notation-migration.md](diagram-notation-migration.md).

**Невалидные рёбра (нарушают relation rules новой нотации)** — **удалять с диаграммы** при миграции. Показывать предупреждение перед переходом: сколько рёбер будет удалено, какие связи затронуты.
