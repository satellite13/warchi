# План: baseline-версии диаграмм

## Цель
- Можно создавать **новую версию** диаграммы (baseline) от текущей.
- По одной диаграмме (model + name) можно **переключаться между версиями**.
- **Старые версии только для просмотра** (без редактирования).

---

## 1. Бэкенд (arepos-server)

### 1.1 Модель и репозиторий
- **Модель**: уже есть — у `Diagrams` есть `version` и уникальность `(model, name, version)`. Менять не нужно.
- **Репозиторий**:
  - Добавить метод выбора диаграмм по модели и имени с сортировкой по версии (например, `findByModelIdAndNameAndDeletedFalseOrderByVersionDesc`) — чтобы на фронте знать «последнюю» версию и список версий.

### 1.2 Эндпоинт «Создать baseline»
- **POST** `/api/v1/diagrams/{id}/baseline`
- Логика:
  - Загрузить диаграмму по `id`, проверить права на редактирование.
  - Вычислить следующую версию по семверу (например, 1.2.3 → 1.3.0), желательно одной функцией/утилитой.
  - Создать новую запись `Diagrams`: те же `name`, `model`, `notation`, `node`, `owner`, `attrs` (копия содержимого), новая версия и новые `createdAt`/`updatedAt`.
  - Проверить отсутствие конфликта по `(model, name, newVersion)`.
  - Вернуть созданную диаграмму (тот же DTO, что и при создании/получении).

### 1.3 (Опционально) Эндпоинт списка версий
- **GET** `/api/v1/diagrams/versions?modelId=...&name=...` — список версий одной диаграммы (id, name, version, createdAt и т.п.) для переключателя версий.
- Альтернатива: не вводить отдельный эндпоинт, а использовать существующий список диаграмм по `modelId` и на фронте фильтровать по `name` и сортировать по версии.

---

## 2. Фронтенд (warchi)

### 2.1 Данные и логика
- **«Версии одной диаграммы»**: из `state.diagrams` отфильтровать по `modelId` и `name` текущей диаграммы, отсортировать по версии (например, через `compareVersions` в убывание) — получится список версий и «последняя» (первый элемент).
- **«Текущая диаграмма — последняя версия?»**: сравнить `activeDiagram.id` с id «последней» версии в этом списке.
- **Режим только просмотр**: если открыта не последняя версия → считать диаграмму read-only (не сохранять изменения, не создавать baseline от неё, канвас в режиме просмотра).

### 2.2 API
- Вызов **POST** `/diagrams/{id}/baseline` (например, из `useApi`). Ответ — новая диаграмма.
- После успешного создания baseline: добавить новую диаграмму в `state.diagrams` и переключить выбор на неё (`selectedDiagramId`), либо перезагрузить модель.

### 2.3 UI — переключатель версий
- В шапке редактора диаграммы (рядом с названием/версией) или в панели настроек:
  - **Селект/дропдаун версий**: список версий одной диаграммы (model + name), отсортированный по убыванию версии.
  - При выборе другой версии — обновить `selectedDiagramId` на выбранную диаграмму (та же логика, что при открытии диаграммы из дерева).
  - Для не-последней версии показывать подпись вида «Только просмотр» / «Базовая версия».

### 2.4 UI — кнопка «Создать базовую версию»
- Кнопка в шапке или в меню диаграммы.
- Доступна только для **последней** версии (для старых — скрыта или disabled).
- По нажатию: запрос POST baseline, затем обновление списка диаграмм и переключение на новую версию; при ошибке — сообщение пользователю.

### 2.5 Канвас в режиме только просмотр
- В **ModelDiagramCanvas** передавать проп, например `readOnly: boolean` (true, если открыта не последняя версия).
- При `readOnly === true`:
  - **Не** вызывать `enableInteractions()` (или вызывать `disableInteractions()` при переключении в read-only), чтобы отключить перетаскивание, ресайз, связи, контекстное меню, редактирование подписей.
  - Кнопки зума/фита в тулбаре могут продолжать работать через вызовы методов рендерера (zoom/pan), если они не завязаны на InteractionManager.
- Итог: для старых версий — только просмотр и навигация по канвасу (зум/фит), без редактирования.

### 2.6 Запрет сохранения и прочие правки для старых версий
- При открытой не-последней версии:
  - Кнопку «Сохранить» не показывать или делать disabled.
  - Не помечать диаграмму как dirty при любых действиях на канвасе (в read-only режиме канвас не эмитит изменения).
- Документ/нотация: при желании — для старых версий не показывать кнопки редактирования документа, только просмотр.

## 4. Порядок внедрения (кратко)
1. Бэкенд: метод репозитория для списка версий по model+name, утилита bump версии, POST `/diagrams/{id}/baseline`.
2. Фронт: вычисление «последней» версии и списка версий, флаг read-only, вызов API baseline и обновление состояния.
3. Фронт: проп `readOnly` в ModelDiagramCanvas и отключение взаимодействий при просмотре.
4. Фронт: переключатель версий и кнопка «Создать базовую версию» в UI.
5. Локализация и проверка сценариев (создание baseline, переключение, сохранение только для последней версии).
