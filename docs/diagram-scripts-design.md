# Диаграммные скрипты: отчёт, раскладка и дополнение холста

Дата: 2026-08-22  
Репозитории: `warchi` (исполнение), `arepos-server` (уже существующие search / neighbors; новых write API нет)  
Ветка (когда дойдёт до реализации): `feat/diagram-scripts-apply`

Это **не** отчёт дубликатов дерева (`docs/model-validation-report-design.md`). То дерево
считает сервер. Здесь — пользовательский JS на **открытой диаграмме**.

## Цель

Один каталог скриптов, один запуск. Скрипт может:

1. проверить холст и написать отчёт (не хватает Location, лишний компонент);
2. двигать / масштабировать / выравнивать / складывать фигуры;
3. доложить на диаграмму уже существующие в модели ноды и связи, найдя их
   запросами, без выгрузки всего дерева.

Скрипт не объявляет вид. Хост смотрит, что он накопил: только issue или ещё
команды записи.

## Границы v1

Входит:

- снимок только открытой диаграммы (instance + нотация + использованные типы);
- async query: `neighbors`, `searchNodes`, `linksBetween`;
- `report.*` и очередь `apply.*`;
- превью изменений и применение одной history-транзакцией;
- `align` / `distribute` / `stack` через уже существующие операции редактора.

Не входит:

- запись в граф модели (create/update/delete нод и связей дерева);
- полный `ctx.model.nodes` / `ctx.model.links`;
- отдельный JS-runner и новые API-ключи;
- поле «тип скрипта» в каталоге;
- запуск без открытой диаграммы.

`findDuplicateLinks` / `nodesOfType` смотрят **срез холста**, не всю модель.
Дубликаты дерева — серверный отчёт валидации.

## Запуск

Кнопка «Скрипты» в редакторе. Без открытой диаграммы «Запустить» неактивна.

Права:

- прогон с пустой очередью `apply` — просмотр скрипта и просмотр модели;
- непустая очередь — плюс редактирование модели и обычный lock диаграммы
  (диаграмма уже открыта в редакторе).

Timeout — на весь прогон вместе с RPC, не на каждый запрос. По timeout очередь
команд отбрасывается, issue можно показать частично или не показывать — в v1
не показывать: прогон считается ошибочным.

## Снимок

В iframe уходит не дерево модели.

```ts
ctx.diagram = {
  id: string
  name: string
  notationId: string
  instances: Array<{
    id: string
    modelNodeId: string
    x: number
    y: number
    width?: number
    height?: number
  }>
  edges: Array<{
    id: string
    modelLinkId: string
    sourceInstanceId: string
    targetInstanceId: string
  }>
}
ctx.notations = /* нотация этой диаграммы */
ctx.types = /* node/link types, реально использованные на холсте */
```

`diagramNodes` / `diagramLinks` читают этот срез (ноды/связи модели, на которые
ссылаются instance/edge). `componentForNode` / `relationRules` — нотация снимка.

Песочница по-прежнему `sandbox="allow-scripts"` без same-origin. Сети у скрипта
нет: только RPC на хост.

## API скрипта

Все вызовы query/apply — async. Скрипт пишется как async-тело (хост оборачивает
источник в async function).

### report

Как сейчас: `report.error|warn|info(message, target?)`. Target: instance/node/link
id. Клик по issue выделяет сущность на холсте.

### query (RPC → существующий REST)

| Функция | Куда ходит хост |
|---|---|
| `neighbors(nodeId, { direction, linkType?, page? })` | `GET /models/{id}/graph/neighbors` |
| `searchNodes({ q?, type?, limit? })` | `GET /search/models/{id}` (nodes) |
| `linksBetween(a, b, { linkType? })` | точечный resolve связей по двум id (существующий resolve/neighbors), не полный список links модели |

Лимиты как у REST (страница neighbors, limit поиска ≤ 50). Хост проверяет, что
`nodeId` принадлежит этой модели.

### apply (только очередь)

Команды не исполняются во время прогона.

| Команда | Смысл |
|---|---|
| `setBounds({ instanceId, x, y, width?, height? })` | геометрия существующего instance |
| `addInstance({ nodeId, x?, y? })` | положить на холст ноду, которая уже есть в модели |
| `addEdge({ linkId })` | положить на холст связь, которая уже есть в модели; оба конца должны оказаться на диаграмме после очереди (уже были или добавлены раньше в этой же очереди) |
| `removeInstance({ instanceId })` | снять фигуру с диаграммы, нода в дереве остаётся |
| `removeEdge({ edgeInstanceId })` | снять ребро с диаграммы, связь в дереве остаётся |
| `align({ instanceIds, mode })` | существующий align редактора / papirus `alignNodes` |
| `distribute({ instanceIds, axis })` | существующий `distributeNodes` |
| `stack({ instanceIds, mode })` | если редактор умеет вложить в контейнер/группу — эта операция; иначе пачка `setBounds` (упаковать друг на друга / стопкой). Новую модель группировки не вводим |

Недопустимые команды (чужой id, нода не из модели, create node/link) хост
отбрасывает на этапе превью с ошибкой прогона — «Применить» недоступно.

## Протокол iframe

Расширение текущего `run` / `ready` / `done`:

1. Хост шлёт `run` с узким снимком (без полного дерева).
2. Песочница шлёт `query` `{ requestId, method, args }`.
3. Хост отвечает `queryResult` `{ requestId, data | error }`.
4. Песочница шлёт `done` `{ requestId, issues, commands, error? }`.

`apply.*` только пушит в `commands` внутри песочницы, на хост до `done` не ходит.

## Превью и применение

После успешного `done`:

1. Список issue (как сейчас).
2. Если `commands.length > 0` — сводка: сколько add/remove/move/align.
3. «Закрыть» — ничего не писать.
4. «Применить» — только при праве edit и непустой очереди.

Применение: одна history-транзакция редактора. Либо все команды, либо ничего
(ошибка посередине → undo этой транзакции). Используются те же функции, что
ручное редактирование (`addExistingNodeToDiagram`, place existing link, resize,
align). Диаграмма становится dirty; save — обычный batch-save.

После применения отчёт (issue) остаётся. Повторный запуск берёт актуальный холст.

Если `commands` пустые — блок «Применить» не показывается, сразу отчёт.

## Каталог и справка

Сущность скрипта не меняется (нет semver, нет поля kind). Шаринг VIEW/EDIT как
сейчас.

In-app help (`validation-scripts.md` / `.en.md`) заменить «скрипт только
репортит» на три примера: проверка холста, раскладка, «добавить соседей по
типу связи». Явно написать: дерево модели скрипт не выгружает и не меняет.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Диаграмма не открыта | Запуск недоступен |
| Timeout / падение скрипта | Ошибка прогона, команд нет |
| Query к чужой модели / битый id | ошибка в `queryResult`, скрипт может поймать |
| Команда с несуществующим instance | прогон ошибка, Apply скрыт |
| Apply без права edit | кнопки нет, issue видны |
| Lock потерян к моменту Apply | ошибка, холст не менять |

## Проверка

- Снимок не содержит всех нод модели: в payload iframe только instance открытой
  диаграммы.
- Валидационный скрипт без `apply` даёт тот же UX отчёта, что сейчас.
- Layout: `align` + Apply → Undo возвращает позиции.
- Enrich: `neighbors` не вызывает `GET /nodes` без фильтра; `addInstance` не
  создаёт ноду в дереве.
- Смешанный скрипт: issue + команды → превью → Отмена не меняет холст.
- `addEdge` без обоих концов на холсте (и не добавленных в очереди) — отказ.

## Связь с уже существующим

- Песочница и каталог — текущие validation scripts.
- Поиск и соседи — Stage 3 REST, без новых backend write API.
- Дубликаты дерева — `docs/model-validation-report-design.md`, не этот API.
- Будущий runner для произвольного JS по дереву этим не открывается.
