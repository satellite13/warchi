# Встроенный отчёт валидации модели и схлопывание дубликатов

Дата: 2026-08-22  
Репозитории: `warchi`, `arepos-server`  
Ветка (когда дойдёт до реализации): `feat/model-validation-report`

## Цель

Дать в модели отдельный отчёт по дубликатам дерева — без выгрузки всего графа
в браузер и без пользовательского JS на полном снимке.

Пользователь открывает модель, нажимает кнопку рядом с матрицей связей и видит
группы дубликатов экземпляров и связей. В группе можно посмотреть, на каких
диаграммах стоит каждый член, выбрать кого оставить и схлопнуть пару атомарно
на сервере.

## Зачем не скрипты

Диаграммные скрипты остаются в браузере: их контекст — открытый холст.

Скрипты со скоупом «вся модель» в v1 не делаем. Произвольный JS по дереву
потребовал бы отдельный runner; для двух конкретных проверок это избыточно.

Отдельные API-ключи для этого отчёта не нужны. Доступ — cookie-сессия и право
на модель (просмотр для GET, редактирование для merge), как у матрицы.

## Границы v1

Входит:

- две проверки: дубликаты узлов и дубликаты направленных связей;
- страница отчёта в модели;
- мастер слияния одной пары (узел или связь);
- атомарные write API на arepos.

Не входит:

- пользовательские скрипты по всему дереву и отдельный JS-runner;
- нечёткий поиск по имени;
- слияние всей группы разом;
- проверка «связь недопустима нотацией»;
- перенос wiki/documents с удаляемой сущности;
- service account / генерация ключей в админке.

## Правила совпадения

### Узлы

Дубликат — два и более узла одной модели с одним `nodeTypeId` и одним именем
после `trim` без учёта регистра.

Тип с именем `directory` (без учёта регистра) не участвует. В продукте только
Directory может быть родителем в дереве; обычный компонент — лист.

Итоговое отображаемое имя группы — имя выбранного для показа члена (как в
дереве, без принудительного lowercase). Ключ группы для API можно нормализовать.

### Связи

Дубликат — два и более ребра с одним `sourceId`, одним `targetId` и одним
`linkTypeId`. Направление учитывается: `A→B` и `B→A` одного типа — не дубликат.

## Контракт отчёта

`GET /api/v1/models/{id}/validation-report`

Право: просмотр модели. Read-only, без attrs.

Сервер считает две проверки SQL `GROUP BY` по проекции (`id`, имена, типы,
концы связи). `attrs` и полный граф в JSON не выгружаются.

```json
{
  "modelId": "…",
  "generatedAt": "2026-08-22T12:00:00Z",
  "duplicateNodes": [
    {
      "nodeTypeId": "…",
      "nodeTypeName": "Application Component",
      "name": "CRM",
      "count": 2,
      "nodes": [
        { "id": "…", "name": "CRM", "parentId": "…" }
      ]
    }
  ],
  "duplicateLinks": [
    {
      "sourceId": "…",
      "sourceName": "A",
      "targetId": "…",
      "targetName": "B",
      "linkTypeId": "…",
      "linkTypeName": "Serving",
      "count": 2,
      "links": [{ "id": "…" }]
    }
  ]
}
```

Все группы возвращаются. Если в группе больше 50 членов, в массиве первые 50
плюс поле `count` с полным размером. Merge вызывается по id, а не по индексу
в усечённом списке.

Диаграммы в отчёт не кладём. При раскрытии члена клиент вызывает
`GET /api/v1/models/{modelId}/diagram-references`. Сейчас endpoint принимает
только `nodeId`. В этой фиче он принимает ровно один из параметров: `nodeId`
или `linkId`. `linkId` возвращает активные диаграммы, в attrs которых есть
instance с этим `modelLinkId`.

## Preview мастера

Клиент не собирает инцидентные связи A/B сам.

`GET /api/v1/models/{id}/validation/merge-nodes-preview?keepId=&dropId=`  
`GET /api/v1/models/{id}/validation/merge-links-preview?keepId=&dropId=`

Право: просмотр модели.

Если пара не является дубликатом по правилам выше — `400`.

Preview узлов возвращает:

- attrs/type properties `keep` и `drop` (не component properties инстансов);
- уникальные связи `drop` (каждую: id, тип, направление, другой конец);
- связи между `keep` и `drop` (только для текста «будут удалены», не для выбора);
- число diagram instance у каждого;
- `hasChildren` / `hasDocuments` у `drop` (флаги для отказа или предупреждения).

Preview связей — attrs обеих связей и список диаграмм, где стоит каждое ребро.

**Уникальная связь `drop`:** после подстановки `drop→keep` не существует связи
`keep` с тем же `linkTypeId`, тем же вторым концом и тем же направлением.

- `drop→X` уникальна, если нет `keep→X` того же типа;
- `X→drop` уникальна, если нет `X→keep` того же типа;
- `keep↔drop` в уникальные не входят.

## Правила merge узла

Пользователь выбирает `keep` (A) и `drop` (B), по одной паре за раз.

1. Итоговые attrs A собираются в мастере пополям (diff A | B | итог).
   Совпадающие поля свёрнуты. Это type properties / attrs ноды.
   Component properties остаются на diagram instance.
2. Уникальные связи B: пользователь отмечает, какие перенести.
   Перенос — `UPDATE` концов этой же связи (`drop` заменяется на `keep`),
   id связи сохраняется, диаграммные рёбра этой связи не надо переписывать.
   Не перенесённые уникальные связи удаляются вместе с их instance на диаграммах.
3. Связи `A↔B` всегда удаляются вместе с instance. Петель `A→A` не создаём.
4. Diagram instance, у которых `modelNodeId = B`, получают `modelNodeId = A`.
   Если A и B были на одной диаграмме, остаются две фигуры одного экземпляра A.
5. A остаётся в своей папке и со своим именем (орфография A). B удаляется.
6. Если у B есть дети — отказ `400`. В продукте у компонента детей нет;
   защита на случай импорта/MCP.
7. Wiki/documents, привязанные к B, в v1 не переносятся и уходят вместе с B.
   Если `hasDocuments` — предупреждение на шаге подтверждения, не отдельный диалог.
8. Нужно право редактирования модели.

## Правила merge связи

1. Итоговые attrs оставшейся связи — тот же пополевый diff.
2. Diagram edge, ссылавшиеся на `drop`, переписываются на `keep`.
   Два ребра на одном холсте после схлопывания ссылаются на одну связь.
3. `drop` удаляется.

## Write API

Право: редактирование модели.

`POST /api/v1/models/{id}/validation/merge-nodes`

```json
{
  "keepId": "…",
  "dropId": "…",
  "attrs": {},
  "transferLinkIds": ["…"],
  "keepUpdatedAt": "…",
  "dropUpdatedAt": "…"
}
```

`POST /api/v1/models/{id}/validation/merge-links`

```json
{
  "keepId": "…",
  "dropId": "…",
  "attrs": {},
  "keepUpdatedAt": "…",
  "dropUpdatedAt": "…"
}
```

`attrs` — полный итоговый объект, не patch.

Сервер в одной транзакции:

- проверяет, что пара всё ещё дубликат;
- сверяет `updatedAt` keep/drop (несовпадение → `409`);
- проверяет, что каждый `transferLinkId` — уникальная связь `drop` (иначе `400`);
- применяет правила выше;
- если любая затрагиваемая диаграмма заблокирована другим пользователем — `409`
  с той же семантикой lock, что batch-save / diagram-lock;
- bump `updatedAt` затронутых сущностей так, чтобы live sync/poll подхватили
  удаление B и перепись instance.

Клиент не патчит граф и диаграммы сам.

## UI

Маршрут: `/models/:id/validation` (`model-validation`).  
Кнопка в `ModelEditorHeader` рядом с матрицей (`grid_view`).

Шапка как у матрицы: назад в редактор этой модели, имя модели, заголовок
«Валидация».

Страница не вызывает `loadModelEditorData`. Только report + ленивые references
+ preview при открытии мастера.

Состояния: загрузка, ошибка, пусто (дубликатов нет), две секции «Экземпляры»
и «Связи» с числом групп.

Карточка группы узлов: тип + имя + бейдж `N копий`. Внутри — члены, родитель-папка,
чипы диаграмм. Пользователь отмечает keep; у остальных — «Слить в выбранный».

Карточка группы связей: `A → B · Serving · N копий`, тот же выбор survivor.

Клик по чипу диаграммы — `/models/:id?diagramId=…&nodeId=…` или
`…&linkId=…`. Редактор уже открывает диаграмму по `diagramId`; в этой фиче
добавляется фокус дерева на `nodeId` и выделение связи по `linkId` после
догрузки scope. Lock диаграммы берётся только если пользователь остаётся на
холсте (текущее поведение открытия диаграммы), не из отчёта «просто посмотреть».

Клик по имени узла без диаграммы — `/models/:id?nodeId=…`: догрузить путь в
дереве и выделить узел, диаграмму не открывать.

Мастер — модалка на странице отчёта, не отдельный роут.

1. Свойства: таблица поле / A / B / итог.
2. Связи (только узлы): уникальные связи B — перенести или нет; текст что A↔B
   удалятся.
3. Подтверждение: кто останется, кто удалится, сколько instance будет переписано,
   предупреждение про documents B. Затем POST.

Успех: тост, закрыть модалку, заново запросить report.  
`409`: не повторять merge молча; предложить обновить отчёт.

Диаграммные скрипты и их модалка в редакторе не меняются.

## Ошибки

| Ситуация | Ответ |
|---|---|
| Нет права просмотра | 403 на GET |
| Нет права редактирования | 403 на POST |
| Пара не дубликат / чужая модель / Directory | 400 |
| У `drop` есть дети | 400 |
| `transferLinkIds` не из уникальных связей `drop` | 400 |
| `updatedAt` keep/drop разошёлся | 409 |
| Диаграмма заблокирована другим | 409 lock |
| `drop` уже удалён | 409 |

## Проверка

arepos-server:

- grouping узлов (trim + case, Directory вне выборки);
- grouping связей (направленный);
- `diagram-references?linkId=` (ровно один из `nodeId`/`linkId`);
- merge узлов: перенос связи с сохранением id, удаление A↔B, remap instance,
  две фигуры A на одной диаграмме, удаление B, отказ при детях, 409 по
  `updatedAt` и lock;
- merge связей: remap edge, сохранение двух рёбер keep на одной диаграмме.

warchi:

- кнопка и маршрут;
- сборка групп и мастер (выбор keep/drop, diff полей, transfer checkboxes);
- после успеха отчёт обновляется;
- переход в редактор не грузит полный snapshot.

i18n: все строки `ru` и `en` в `src/i18n/messages.ts`.

## Связь с уже существующим

- Паттерн навигации — как `/models/:id/relation-matrix`, но без клиентского
  full-load.
- `findDuplicateLinks` в диаграммных скриптах не удаляем: это другой скоуп.
- Будущий JS-runner для модельных скриптов этим отчётом не блокируется и не
  требуется для v1.
