# Администрирование

Разделы администрирования доступны пользователям с правом просмотра админ-панели (`ADMIN_PANEL:VIEW`). На практике это обычно пользователи с ролью **ADMIN**.

## Пользователи

В разделе управления пользователями доступны:

- поиск по email;
- смена роли (`admin` / `architect` / `editor` / `reader` / `viewer`);
- активация и блокировка аккаунта;
- редактирование профиля пользователя;
- смена пароля пользователя;
- просмотр и **отзыв API-ключей** пользователя (секрет не показывается; отзыв сразу блокирует MCP и обмен ключа на JWT);
- **дополнительные feature-гранты** пользователя (allow-only extras сверх матрицы роли).

Изменения применяются сразу после подтверждения действия.

## Гранты ролей

Раздел **Гранты ролей** (`/admin/role-grants`) — матрица UI-возможностей (feature grants) по ролям.

Feature grants **не заменяют** ACL ресурсов (владение, shares, Cerbos): они только показывают или скрывают действия в интерфейсе поверх уже выданных прав на объекты. Доступ к данным по-прежнему решает серверная авторизация ресурсов.

Роли продукта:

| Роль | Назначение |
|------|------------|
| `admin` | Администрирование; **всегда** имеет все feature-гранты (матрица для admin не редактируется) |
| `architect` | Полная работа с моделями и каталогами (по умолчанию широкий набор грантов) |
| `editor` | Редактирование моделей и связанных сущностей в рамках ACL |
| `reader` | Чтение и ограниченный набор UI-действий |
| `viewer` | Минимальный просмотр |

Администратор может:

- менять матрицу грантов для `architect` / `editor` / `reader` / `viewer`;
- выдавать отдельному пользователю **дополнительные** ключи (только расширение allow-list, без отбора грантов роли).

> **Фаза 1:** feature grants применяются только на клиенте (кнопки, меню, soft-guard маршрутов). API пока **не** отклоняет запросы из‑за отсутствия гранта — серверные ACL и политики Cerbos остаются отдельным слоем.

## Удалённые сущности

Раздел **Удалённые** показывает сущности, удалённые из каталогов (**мягкое удаление**). В каталогах модели, нотации, типы и формы пропадают из рабочих списков, но остаются здесь, пока администратор не удалит их навсегда.

Секции списка:

- удалённые модели;
- удалённые нотации;
- удалённые типы узлов;
- удалённые типы связей;
- удалённые формы.

Возможности:

- просмотр списка удалённых сущностей;
- **безвозвратное удаление** (permanent delete) по подтверждению.

Безвозвратное удаление может быть **заблокировано** (HTTP 409), если сущность ещё используется: например, нотация в активных моделях или тип в компонентах, нодах и связях.

> Permanent delete нельзя отменить. Рекомендуется выполнять только после проверки, что сущность действительно не нужна. Восстановления из корзины в интерфейсе нет.

## Блокировки диаграмм

Раздел **Блокировки диаграмм** (`/admin/diagram-locks`) показывает активные блокировки редактирования холста.

Возможности:

- список активных блокировок с путём «модель / диаграмма» и владельцем блокировки;
- автоматическое обновление списка (live);
- **принудительное снятие** блокировки после подтверждения — когда редактор «завис» или нужно срочно передать холст другому пользователю.

Обычная блокировка при совместной работе описана в разделе [Диаграммы](/docs/diagrams). Админское снятие — исключительный инструмент; после force-release другой пользователь с правом EDIT может снова захватить холст.

## Иконки

Раздел **Иконки** (`/admin/icons`) — общая библиотека SVG инстанса.

- загрузка одного или нескольких SVG;
- экспорт и импорт бандла `warchi-icon-bundle`;
- импорт иконок из JSON экспорта нотации (берётся только `icons[]`, нотация не создаётся);
- удаление иконки (ссылки в нотациях перестанут резолвиться).

Обычные пользователи только выбирают эти иконки в пикере. Импорт нотации библиотеку не пополняет.

Связанный раздел по ролям и feature grants — [Авторизация](/docs/auth).
