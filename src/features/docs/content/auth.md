# Авторизация и доступ

## Вход в систему

После успешного входа сервер создаёт cookie-сессию, а приложение сохраняет только профиль пользователя для отображения интерфейса. JWT не хранится в `localStorage` или `sessionStorage`. Если пользователь пытался открыть защищённую страницу до входа, после авторизации выполняется возврат на эту страницу; иначе открывается главная. При неуспешном входе показывается сообщение об ошибке.

## Регистрация

После успешной регистрации создаётся сессия и выполняется переход на главную страницу. Дальнейшие переходы в защищённые разделы доступны без повторного входа, пока сессия активна.

## Роли

- **USER** — работа со своими сущностями и теми, к которым выдан доступ.
- **ADMIN** — дополнительные административные функции (управление пользователями, удалённые сущности, принудительное снятие блокировок диаграмм).

## Защита маршрутов

- Страницы, требующие авторизации, недоступны без активной сессии.
- Попытка открыть защищённый маршрут без входа перенаправляет на страницу логина.
- Доступ к админ-разделу проверяется по правам (`ADMIN_PANEL:VIEW`) через policy-проверку.

## Обновление сессии

При истечении cookie-сессии клиент пытается обновить её через `/auth/refresh`. Если сервер явно отклоняет обновление, локальное состояние сессии очищается и требуется повторный вход. При временной сетевой ошибке приложение не очищает сессию сразу и даёт возможность повторить запрос.

## Выход

При выходе приложение сначала вызывает серверный logout, чтобы удалить httpOnly cookies. Локальное состояние очищается после успешного ответа сервера.

## Недоступность сервиса

Если API или сервис авторизации временно недоступны, поверх интерфейса показывается блокирующий экран с кнопкой повтора. Пока блокер активен, работа с данными недоступна — дождитесь восстановления или нажмите «Повторить».
