# Диаграммы

Диаграмма — это графическое представление архитектурной модели. Каждая модель может содержать одну или несколько диаграмм.

## Управление диаграммами

### Создание диаграммы

1. В панели дерева нажмите кнопку создания диаграммы
2. Укажите название и выберите нотацию
3. Версия подбирается автоматически — если диаграмма с таким именем уже есть, минорная версия увеличивается

### Переключение между диаграммами

Кликните по нужной диаграмме в дереве модели. Если есть несохранённые изменения, система предложит:

- **Сохранить и переключить** — сохранить текущие изменения, затем открыть новую диаграмму
- **Не сохранять** — отменить изменения и переключиться
- **Отмена** — остаться на текущей диаграмме

### Создание baseline (новой версии диаграммы)

Baseline — это новая версия текущей диаграммы, созданная на основе её текущего состояния.

Как создать baseline:

1. Откройте нужную диаграмму в редакторе модели
2. Вызовите действие создания новой версии диаграммы (baseline)
3. Подтвердите создание — система создаст следующую версию и откроет её

Что важно:

- baseline копирует состав и расположение элементов из исходной диаграммы на момент создания;
- в переключателе версий можно перейти к любой версии диаграммы;
- редактирование доступно только для последней версии, предыдущие версии открываются в режиме только чтение.

#### Когда делать baseline

Рекомендуется создавать baseline перед изменениями, которые могут заметно поменять структуру диаграммы:

- перед авторазмещением большого количества узлов;
- перед массовым редактированием связей или типов отображения;
- перед переработкой группировки и компоновки подсистем;
- перед экспериментами с альтернативным вариантом представления архитектуры.

Пример сценария:

1. Текущая диаграмма согласована и используется как рабочая версия.
2. Нужно попробовать новую компоновку (например, переразбить систему на подсистемы).
3. Создаётся baseline.
4. Изменения выполняются в новой версии.
5. Если вариант удачный — работа продолжается в новой версии; если нет — можно вернуться к предыдущей версии как к опорной.

### Копирование диаграммы в другую модель

Действие **«Копировать диаграмму в другую модель»** (в строке дерева и в редакторе) открывает мастер: выберите существующую целевую модель, нотацию для новой диаграммы и при необходимости измените её имя, версию и папку. Если предпросмотр вернул известную проблему, мастер показывает локализованный текст блокировки или предупреждения.

Мастер сначала сопоставляет элементы с целевой моделью: для узлов — по `stableId`, затем по точному имени и типу; для связей — по `stableId`, затем по типу и конечным точкам. **«Сопоставить»** значит привязать экземпляр к уже существующему узлу/связи в целевой модели, а не к компоненту нотации. Если кандидата нет, мастер сразу ставит **«Создать»**. Неоднозначные совпадения (несколько узлов с тем же именем и типом) остаются без выбора — их нужно сопоставить вручную, создать или пропустить. Нотацию целевой диаграммы выбирает пользователь. При смене целевой модели сопоставления пересчитываются заново.

В первой версии документы и файлы не копируются.

### Сравнение версий диаграммы

Для активной диаграммы можно открыть экран сравнения её версий.

Как открыть:

1. Откройте диаграмму в редакторе модели.
2. В блоке с версией диаграммы нажмите кнопку **«Сравнить версии диаграммы»** (иконка `compare`).
3. В открывшемся экране выберите версии слева и справа.

Особенности сравнения:

- сравнение выполняется в рамках одного имени диаграммы (например, `Context`, версии `1.0.0` и `1.1.0`);
- обе стороны отображаются в режиме только чтение;
- можно переключать базовую сторону кнопкой **«Переключить базу»**;
- переключатель **«Синхронизация»** связывает панораму и масштаб обеих сторон (по умолчанию включён, запоминается в браузере);
- по клику на элемент внизу показывается таблица свойств **было/стало**;
- поддерживается сравнение маршрута связи и её параметров.

Когда использовать:

- после создания baseline, чтобы быстро увидеть фактические изменения;
- перед согласованием новой версии диаграммы с командой;
- перед публикацией ссылки на актуальное визуальное состояние.

### Переход на новую версию нотации

Если для нотации активной диаграммы есть более новая версия (созданная копированием из текущей) и диаграмма доступна для редактирования, над холстом появляется баннер с кнопкой **«Перейти»**. На старых версиях диаграммы (только просмотр) баннер не показывается.

Что делает переход:

1. меняет `notationId` у текущей диаграммы на выбранную версию;
2. сопоставляет компоненты и отношения **по имени** (при неоднозначности — ещё и по типу ноды/связи);
3. добавляет привязки и scoped-свойства под новую нотацию для элементов на этой диаграмме;
4. **не удаляет** старые привязки на нодах/связях модели (они могут использоваться другими диаграммами).

После перехода сохраните модель. Если какой-то компонент или отношение с диаграммы не находится в новой версии по имени, миграция отменяется с сообщением об ошибке.

Если нотация диаграммы мягко удалена, в шапке всё равно показываются её имя и версия (с пометкой «удалена»), пока диаграмма на неё ссылается — удобно как раз для перехода на живую копию.

### Закрытие и удаление

- **Закрыть** — кнопка на панели инструментов. Диаграмма остаётся в модели, но закрывается из редактора
- **Удалить** — действие в строке дерева. Диаграмма будет удалена при сохранении

## Редактор диаграмм

Редактор диаграмм предоставляет графический холст для размещения и соединения компонентов модели.

### Блокировка редактирования

На **одну диаграмму** в момент времени может **редактировать на холсте только один пользователь**. При открытии диаграммы клиент запрашивает блокировку; пока она у вас, другие пользователи с доступом обычно видят эту диаграмму в режиме **только просмотр** (без перемещения элементов и без сохранения правок холста).

- В **дереве модели** у диаграммы показывается, **кто держит блокировку** — вы или другой участник.
- Если вы открыли диаграмму, пока её редактировал кто-то другой, после освобождения блокировки можно воспользоваться действием вроде **«Попробовать редактировать»** (повторный запрос блокировки).
- Если вы были в просмотре и диаграмма на сервере **уже обновилась**, система может предложить **«Загрузить с сервера»**, чтобы подтянуть актуальное состояние.
- Блокировка **периодически продлевается**, пока открыт редактор; при длительном бездействии или обрыве сессии она может **истечь** — тогда другой пользователь сможет начать редактирование.
- **Администраторы** могут принудительно снять «зависшую» блокировку через раздел администрирования.

Изменения в **дереве модели**, **связях** и других сущностях вне занятой диаграммы по-прежнему сохраняются кнопкой **«Сохранить»** в редакторе модели; при параллельных правках возможен **конфликт при сохранении** — см. [Модели → Сохранение](/docs/models).

### Добавление элементов

Элементы можно добавить на диаграмму несколькими способами:

1. **Перетаскивание из палитры** — перетащите тип элемента из палитры на холст
2. **Из дерева модели** — перетащите существующий компонент из дерева модели
3. **Заметка или контейнер** — из контекстного меню холста (только на диаграмме, без новой ноды в дереве модели)

### Перемещение и изменение размера

- **Перемещение** — нажмите на элемент и перетащите его в нужное место
- **Изменение размера** — используйте маркеры на краях выделенного элемента
- **Множественное выделение** — зажмите `Ctrl/Cmd` и кликайте по нескольким элементам
- **Рамочное выделение** — `Ctrl/Cmd` + перетаскивание по пустому месту холста

### Соединение элементов

Для создания связи между элементами:

1. Наведите на элемент-источник — на контуре рядом с курсором появится ручка `+` (когда включена **Связь по контуру**; кнопка на панели инструментов, по умолчанию включена)
2. Перетащите ручку к элементу-приёмнику
3. Отпустите кнопку мыши на контуре приёмника

Либо зажмите `Shift` и перетащите с тела элемента — Shift не нужен, если тянете за ручку.

> Если в нотации не настроены правила связей для выбранных типов элементов, соединение будет недоступно.

### Навигация по холсту

- **Масштабирование** — колесо мыши или жесты трекпада
- **Перемещение холста** — перетаскивание по пустому месту, средняя кнопка мыши или `Пробел` + перетаскивание
- **Вписать в экран** — кнопка на панели инструментов, масштабирует холст под все элементы

### Подпись на узле и связи (составная метка)

Текст на фигуре узла или на связи может задаваться **шаблоном** в компоненте или relation нотации: `${name}` — имя ноды или relation, `#{…}` — поля **типа ноды / типа связи**, `${…}` — поля **компонента / relation** (кроме зарезервированного `name`). Значения правятся в **панели свойств** ноды или связи в [редакторе модели](/docs/models). Подробнее — [Модели](/docs/models) и [Нотации → Шаблоны меток](/docs/notations).

|----------|----------|

| Повторить | Повторить отменённое действие (`Ctrl+Y`) |

### Масштаб и навигация

| Действие | Описание |
|----------|----------|
| Приблизить | Увеличить масштаб холста |
| Отдалить | Уменьшить масштаб холста |
| Вписать в экран | Подогнать масштаб под все элементы |
| Масштабировать выделение | Подогнать масштаб под выделенные элементы |

| Сбросить масштаб | Вернуть масштаб и позицию к исходным |

### Отображение

| Действие | Описание |
|----------|----------|
| Сетка | Показать/скрыть сетку на холсте |
| Миникарта | Показать/скрыть миникарту в углу холста |
| Привязка к сетке | Включить/выключить привязку элементов к сетке при перемещении |
| Связь по контуру | Показывать ручку `+` на контуре узла для создания связи без Shift |
| Умное выравнивание / линейки | Направляющие при перетаскивании и линейки по краям холста |
| Режим навигации | Перемещение холста без случайного сдвига элементов |
| Закрепить точки связей | Зафиксировать точки привязки связей (связи не перемещаются при перемещении узлов) |

## Настройки диаграммы

Настройки диаграммы управляют поведением редактора для конкретной диаграммы.

Основные настройки:

- **Автолинки в группах** — при переносе компонента внутрь контейнера редактор может автоматически предложить создать или использовать группирующую связь;
- **Привязка к сетке** — помогает ровно выравнивать элементы при перемещении;
- **Сетка / миникарта / линейки** — визуальные помощники для навигации и компоновки;
- **Закрепление точек связей** — фиксирует привязку концов связей при перемещении узлов.

Практические рекомендации:

- включайте привязку к сетке для аккуратной и регулярной раскладки;
- включайте автолинки в группах, если активно используете контейнерные отношения;
- на больших диаграммах используйте миникарту и линейки для более быстрой навигации.

### Экспорт и данные

| Действие | Описание |
|----------|----------|
| Экспорт в PNG | Сохранить диаграмму как растровое изображение PNG |
| Экспорт в SVG | Сохранить диаграмму как векторное изображение SVG |
| Ссылка на картинку | Открыть диалог получения публичной ссылки на превью диаграммы (см. ниже) |
| Просмотр JSON | Показать JSON-представление данных диаграммы |

### Поделиться картинкой диаграммы

Можно получить ссылку на превью диаграммы в виде SVG. Этой ссылкой можно поделиться с коллегами или вставить картинку в Notion, Confluence, чаты, документы — открыть смогут все, у кого есть ссылка, без входа в систему.

**Как получить ссылку:**

1. Откройте нужную диаграмму в редакторе модели.
2. Нажмите **«Ссылка на картинку»** на панели инструментов.
3. В диалоге выберите тип ссылки:
   - **Эта версия диаграммы** — ссылка всегда будет показывать текущий снимок (подходит для фиксации).
   - **Всегда последняя версия по имени** — ссылка будет показывать последнюю сохранённую версию диаграммы с этим именем (картинка обновится после сохранения).
4. Нажмите **«Получить ссылку»** — превью текущего вида загрузится на сервер и будет сформирована ссылка.
5. Нажмите **«Скопировать ссылку»** или **«Открыть ссылку»**. Диалог остаётся открытым после копирования.

Превью также автоматически загружается при сохранении модели, поэтому по ссылке «всегда последняя» после сохранения будет отображаться актуальное состояние.

## Сохранение

Кнопка **«Сохранить»** на панели инструментов становится активной при наличии несохранённых изменений. Перед сохранением система проверяет обязательные поля: **свойства типа ноды** и **свойства компонента нотации** (где заданы схемы). Если валидация не пройдена, будет показано сообщение об ошибке с указанием конкретного элемента и свойства. Подробнее о сохранении и конфликтах — в разделе [Модели → Сохранение](/docs/models).
