# Работа с моделями

Модели — это основные сущности в wArchi. Каждая модель представляет собой архитектурное описание системы, состоящее из диаграмм, компонентов и связей.

## Список моделей

На странице **Модели** отображается список всех созданных моделей. Модели группируются по имени — каждая группа может содержать несколько версий.

### Создание модели

1. Нажмите кнопку **«Создать модель»** в панели списка
2. Введите название модели
3. Нажмите **«Создать»** для подтверждения

Новая модель создаётся с версией `1.0.0`. Нотацию выбираете позже — **при создании диаграммы**. У одной модели могут быть диаграммы с разными нотациями.

### Переименование модели

Название модели можно изменить непосредственно в заголовке редактора — кликните по названию и введите новое. Также переименование доступно через карточку модели в списке.

### Шаринг модели

Владелец модели может выдать доступ другим пользователям через кнопку **«Поделиться»**:

- **VIEW** — пользователь видит модель и диаграммы;
- **EDIT** — пользователь может редактировать модель и её диаграммы.

В карточке модели отображается текущий уровень доступа.

### Доступ к нотации через модель

Доступ к модели и доступ к нотации — **разные** права. Если у вас есть **EDIT** на расшаренную модель, но нет прямого шаринга на нотацию:

- редактор модели загружает метаданные нотации, компоненты, связи и типы **только для версии нотации, которая уже используется активной диаграммой этой модели**;
- подставить произвольную чужую нотацию по идентификатору, имея лишь права на модель, **нельзя** — это ограничение API;
- для просмотра и редактирования нотации в каталоге **Нотации** владелец по-прежнему должен выдать отдельный шаринг на нотацию.

Клиент передаёт `modelId` при загрузке данных нотации из контекста редактора модели.

### Версионирование

Модели поддерживают семантическое версионирование (SemVer):

- **Major** (основная) — несовместимые изменения архитектуры
- **Minor** (минорная) — добавление новых элементов с сохранением совместимости
- **Patch** (патч) — исправления и мелкие правки

Вы можете создать новую версию модели на основе существующей.

### Сравнение версий модели

Для модели доступен отдельный экран **визуального сравнения версий**.

Как открыть:

1. Откройте нужную модель в редакторе.
2. Нажмите кнопку **«Сравнить с версией»** (иконка `compare_arrows`) в шапке.
3. Выберите версии слева и справа.
4. При необходимости выберите имя диаграммы в **поиске** (список диаграмм можно фильтровать).

Как читать результат:

- экран показывает две диаграммы рядом, обе в режиме только чтение;
- переключатель **«Синхронизация»** связывает панораму и масштаб обеих сторон (по умолчанию включён, запоминается в браузере);
- одна сторона считается **базой**, вторая — **изменениями**;
- кнопку **«Переключить базу»** можно использовать, чтобы поменять интерпретацию изменений;
- при клике на узел или связь снизу открывается таблица свойств **было/стало**;
- для элементов, которых нет на одной из сторон, в таблице отображается `—`.

Подсветка различий:

- **добавлено**;
- **удалено**;
- **изменено**.

Сравнение учитывает не только состав узлов/связей, но и свойства, включая нотационно-специфичные (diagram-scoped) параметры.

## Редактор модели

Редактор модели включает несколько областей. В шапке также доступны **скрипты проверки** модели — см. [Скрипты](/docs/validationScripts).

### Дерево модели (левая панель)

В левой панели отображается иерархическая структура модели:

- **Папки** — для группировки компонентов
- **Компоненты** — элементы архитектуры (сервисы, модули, базы данных и т.д.)
- **Диаграммы** — графические представления модели

Над деревом есть **поиск**: список сужается до совпадений с путём предков, несовпадающие предки приглушаются. После очистки поиска выбранный узел остаётся на виду.

Действия — кнопки в шапке панели и мини-кнопки в строках (контекстного меню нет):

- создать папку, компонент или диаграмму;
- переименовать или удалить элемент;
- скопировать диаграмму в другую модель;
- увидеть, кто держит блокировку холста.

Переключатель в шапке панели синхронизирует выделение между деревом и холстом.

### Палитра

Панель палитры содержит типы элементов **нотации активной диаграммы**. Перетащите элемент из палитры на диаграмму, чтобы добавить новый компонент. Иконка в палитре берётся из поля **«Иконка для палитры»** компонента нотации, если оно задано; иначе — из иконки фигуры.

### Панель свойств (правая панель)

При выборе элемента в дереве или на диаграмме открывается панель свойств (вкладки **Свойства**, **Трассировка**; для узла на диаграмме также **Стиль**):

- **Стиль** (вкладка «Стиль») — внешний вид **экземпляра** на диаграмме (цвет, форма, размеры), с возможностью восстановления стилей из нотации.

#### Composite-элементы в редакторе модели

Для нод, созданных из notation-компонентов с формой **Composite**, вкладка **«Стиль»** показывает дополнительные настройки composite-экземпляра:

- редактирование применённых style-свойств экземпляра;
- восстановление стиля из нотации (когда доступно);
- предпросмотр результата с учетом биндингов и значений свойств ноды.

Практика: сначала обновляйте базовую структуру composite в нотации, а в модели используйте стиль экземпляра только для локальных (diagram-scoped) отклонений.

#### Кастомные свойства узла (вкладка «Свойства»)

Для **ноды** в модели отображаются два независимых блока полей (если они заданы в каталоге типов и в нотации):

1. **Свойства типа ноды** — схема задаётся в разделе [Типы](/docs/types) для соответствующего типа ноды. Значения **одинаковы для этой ноды во всей модели** (на всех диаграммах). У каждого поля в интерфейсе видно, что источник — **тип ноды**, и подсказка **плейсхолдера для подписи на фигуре**: `#{имяСвойства}`.
2. **Свойства компонента нотации** — схема задаётся в [редакторе нотации](/docs/notations) для компонента. Значения **зависят от диаграммы** (у одной и той же ноды на разных диаграммах могут быть разные значения у экземпляров). Плейсхолдер в подписи: `${имяСвойства}`. В интерфейсе — бейдж **компонент**.

Имя ноды в тексте на фигуре задаётся в шаблоне составной метки отдельно: **`${name}`** — это зарезервированное имя, **не** кастомное поле компонента.

Полное описание синтаксиса шаблона подписи — в разделе [Нотации → Шаблоны меток](/docs/notations).

#### Кастомные свойства связи (вкладка «Свойства»)

Для **связи** в модели отображаются два независимых блока полей (если они заданы в каталоге типов и в нотации):

1. **Свойства типа связи** — схема задаётся в разделе [Типы](/docs/types) для соответствующего типа связи. Значения **одинаковы для этой связи во всей модели** (на всех диаграммах). Плейсхолдер в подписи на связи: `#{имяСвойства}`.
2. **Свойства relation** — схема задаётся в [редакторе нотации](/docs/notations) для relation. Значения **зависят от диаграммы** (у одной и той же связи на разных диаграммах могут быть разные значения у экземпляров). Плейсхолдер: `${имяСвойства}`.

Имя relation в тексте на связи задаётся в шаблоне составной метки отдельно: **`${name}`** — зарезервированное имя relation в нотации, **не** пользовательское поле relation. Когда шаблон задан, отображаемый текст строится из шаблона; произвольная метка экземпляра на диаграмме для отображения не используется.

#### Подсказки в панели стилей

Для компактных полей используются короткие обозначения:

- `W/H/R` — ширина, высота, радиус;
- `PT/PB/PL/PR` — количество портов сверху/снизу/слева/справа;
- `T/R/B/L` — отступы сверху/справа/снизу/слева (отступ содержимого и отступ метки).

При наведении курсора на такие поля показывается подсказка с полным названием параметра.
Для блоков отступов доступны режимы синхронизации **Pair** (парами) и **All** (все стороны), подписи кнопок локализуются по текущему языку интерфейса.

Три разных inset в стиле узла (**содержимое**, **метка**, **иконка**) вложены и не взаимозаменяемы: сначала сужается контентная область фигуры, внутри неё — текст и зона иконки. Подробнее — в [Нотации → Отступы содержимого, метки и иконки](/docs/notations).

Левая и правая панели могут быть изменены по размеру и свёрнуты.

### Диаграммы

Модель может содержать несколько диаграмм. Каждая диаграмма — отдельное графическое представление, которое может отображать все или часть компонентов модели. Подробнее о работе с диаграммами — в разделе [Диаграммы](/docs/diagrams).

Для активной диаграммы доступно действие **«Информация о диаграмме»** в тулбаре. Во всплывающем окне показываются:

- имя и версия диаграммы;
- имя и версия нотации;
- владелец нотации (если метаданные доступны).

### Матрица связей

В шапке редактора модели доступна кнопка **«Матрица связей»**. Открывается отдельный экран матрицы связей между типами нод модели (это **не** матрица правил в редакторе нотации: там задают допустимые пары компонентов, здесь смотрят уже созданные связи модели).

- **Без нотации (типы)** — оси «Вертикаль» и «Горизонталь» строятся по **типам нод**; ось «Связи» — по **типам связей** модели.
- При выборе **нотации** оси «Вертикаль» и «Горизонталь» также используют **типы нод**, а ось «Связи» — **типы связей**, которые есть у relations этой нотации. Связь попадает в ячейку по типам нод источника и цели и по **типу связи** (общий id типа связи), а не по имени relation и не по привязке компонента/relation на экземпляре. Имена вроде `relationship` и `flow` сами по себе не сопоставляются.
- Связи, чей тип связи **не используется** ни одним relation выбранной нотации, в матрицу **не попадают** (они вне словаря этой нотации).
- Ячейки, **допустимые по правилам** выбранной нотации (relation rules), визуально выделяются.
- Переключатель **«Только допустимые по правилам»** (при выбранной нотации) оставляет только такие ячейки; **«Скрывать пустые строки и столбцы»** убирает оси без связей.
- Фильтры по осям и типам связей, heatmap по количеству связей в ячейке.
- Клик по ячейке открывает панель деталей со списком связей.
- Экспорт: **CSV long**, **CSV wide**, **PNG**.

Матрица удобна для аудита полноты связей и отчётов без ручного обхода всех диаграмм.

### Импорт Open Exchange (XML)

В шапке редактора доступен мастер **«Импорт Open Exchange (XML)»** для загрузки архитектурной модели из XML (OEF):

1. **Анализ** — выберите целевую нотацию и XML-файл; файл загружается на сервер для разбора (до ~100 МБ), клиент получает компактный JSON и список замечаний.
2. **Маппинг** — сопоставьте типы элементов и связей из файла с компонентами/relations нотации (доступны фильтр «только не смэппленные» и массовое применение).
3. **Предпросмотр** — проверьте объём импорта (ноды, связи, диаграммы) и предупреждения. Здесь же настройки **переиспользования**: создавать новые ноды/связи или искать подходящие уже в модели (нода: имя + тип; связь: концы + тип, опционально метка на диаграмме). При совпадении — только id или обновление свойств из OEF. Диаграммы и папки organizations всегда создаются заново.
4. Нажмите **«Импортировать»** — сущности создаются/обновляются в текущей модели **чанками** (batch-save по частям); в футере мастера показывается прогресс. При ошибке чанка импорт останавливается (уже созданные сущности не откатываются автоматически).

После импорта может открыться **отчёт**: несопоставленные или не сконвертированные свойства, замечания по правилам связей и обязательные поля без значений. Заполните обязательные свойства в панели свойств перед следующим сохранением.

### Пакет модели (экспорт / импорт)

ZIP-пакет модели — способ перенести модель между окружениями, пользователями или сделать резервную копию. В пакет входят:

- метаданные модели, ноды, связи и диаграммы;
- **нотации**, используемые диаграммами (типы, компоненты, relations, правила, формы) — по одному JSON на нотацию;
- **wiki-файлы** и привязки `document_refs`, включая перекрёстные ссылки `mdfile://` между страницами.

Превью диаграмм (SVG) в пакет **не** входят — они создаются заново при сохранении или при публикации ссылки на диаграмму из редактора.

**Экспорт** доступен с карточки модели в списке (иконка скачивания) и из шапки редактора. **Импорт** — кнопка **«Импорт пакета модели»** в панели списка: выбираете ZIP, сервер создаёт **новую** модель у текущего пользователя (объединение с существующей моделью не поддерживается). Пока идёт импорт, показываются этапы задания (очередь, проверка архива, нотации, файлы, модель, ссылки на документы). При успехе открывается редактор новой модели; если есть предупреждения, они показываются после импорта. Импорт пакета **не** добавляет SVG в библиотеку иконок: если в нотациях есть имена, которых нет в каталоге и в библиотеке инстанса, появится предупреждение — администратор загружает их на [Админка → Иконки](/docs/admin).

Если нотация с тем же **именем и версией** уже есть и у вас есть право на просмотр, импорт **переиспользует** её (компоненты и отношения сопоставляются по имени и типу). Если нотация недоступна или структура несовместима — импорт завершится ошибкой с указанием причины.

Если модель с тем же **именем и версией** уже есть, откроется диалог: можно **переименовать** модель и/или **сменить версию** и повторить импорт **без повторной загрузки** ZIP.

## Сохранение

Кнопка **«Сохранить»** на панели инструментов активна при наличии несохранённых изменений. Индикатор (точка) на кнопке показывает, что есть незафиксированные изменения. Перед сохранением проверяются обязательные поля: в том числе **свойства типа ноды** и **свойства компонента нотации** у нод с соответствующими схемами.

При переключении или закрытии диаграммы с несохранёнными изменениями система предложит сохранить, отменить или вернуться к редактированию.

### Конфликт при сохранении

Если вы и другой пользователь **изменили одну и ту же ноду, связь или диаграмму** так, что версия на сервере уже другая, при нажатии **«Сохранить»** пакетное сохранение может быть **отменено** — чтобы не затереть чужие правки без предупреждения. Откроется диалог **«Конфликт при сохранении»**:

- Вверху — **два поясняющих блока** (вариант «подтянуть с сервера» и вариант «перезаписать сервер»), чтобы было ясно, чем они отличаются.
- Ниже — **список конфликтных сущностей** с подписью времени: от какого состояния вы правили и когда последний раз менялось на сервере.
- У **каждой строки** можно раскрыть сравнение: в таблице показываются **только поля, где ваш черновик и сервер расходятся** (основные поля и ключи верхнего уровня в `attrs`). Время «от какой версии правили» смотрите в подписи к строке списка, в таблице оно не повторяется. Данные с сервера подгружаются отдельным запросом по id; пока идёт загрузка, таблица скрыта.
- Под вводным текстом указано: пока окно открыто, **второй** диалог конфликта сам не появится; после того как вы выберете действие и снова нажмёте **«Сохранить»**, сервер проверяется заново — если за это время кто-то ещё сохранил изменения, **конфликт может отобразиться снова**.

Доступные действия внизу окна (нужно выбрать **один** из двух основных сценариев):

- **Подтянуть с сервера** — **полная перезагрузка модели** из API. Ноды и связи из списка конфликта получают **актуальные значения с сервера** по всем полям (в том числе attrs), чтобы не затирать чужие правки в дереве; где у вас и на сервере было одинаково, так и останется. Если в списке **диаграмма**: метаданные и attrs (кроме холста) с сервера; если расходился блок экземпляров на холсте — сохраняется **ваша** версия холста (параллельно с вами холст не редактируют). Затем снова нажмите **«Сохранить»**.  
  **Внимание:** несохранённые правки по **другим** объектам модели (не в списке конфликта) при полной перезагрузке **пропадут** — остаётся то, что пришло с сервера, плюс особый случай с холстом диаграммы, описанный выше.
- **Перезаписать сервер моими данными** — повторное сохранение с принудительной перезаписью; правки других пользователей по этим объектам будут потеряны.
- **Отмена** — закрыть диалог; несохранённые правки остаются локально, но завершить сохранение без выбора стратегии нельзя.

Тексты кнопок и подсказок совпадают с локализацией приложения (раздел `models` в интерфейсе).

Одновременное **редактирование открытой диаграммы на холсте** у двух пользователей ограничивается **блокировкой** (один редактор на диаграмму) — см. раздел [Диаграммы](/docs/diagrams).

### Live sync между пользователями

Для открытого редактора модели используется live sync:

- при изменениях в модели от других пользователей клиент подтягивает актуальные данные модели, нод, связей и диаграмм;
- синхронизация работает через WebSocket-уведомления с защитным fallback на периодический polling;
- у себя в текущей вкладке вы продолжаете видеть локальный черновик несохранённых изменений, а конфликтующие записи при сохранении обрабатываются через диалог конфликта.

## Удаление модели

Для удаления модели используйте кнопку удаления в списке моделей. Это **мягкое удаление**: модель пропадает из каталога, данные остаются до **безвозвратного удаления** в разделе [Администрирование → Удалённые](/docs/admin). Восстановления из корзины в интерфейсе нет.
