# Нотации

Нотация определяет визуальное представление и правила для архитектурных диаграмм. Она задаёт, какие типы элементов доступны и как они отображаются.

## Список нотаций

На странице **Нотации** отображается список всех нотаций, сгруппированных по имени. Каждая нотация может иметь несколько версий.

### Создание нотации

1. Нажмите кнопку **«Создать»** в заголовке списка
2. Введите название нотации
3. Нажмите **«Создать»** для подтверждения

### Шаринг нотации

Для нотаций также доступен шаринг через кнопку **«Поделиться»**:

- **VIEW** — просмотр нотации;
- **EDIT** — изменение компонентов, relations и правил связей.

При работе с шареными ресурсами доступные действия определяются выданным уровнем прав.

### Экспорт и импорт нотации

**Экспорт** доступен из меню карточки в списке и из шапки редактора нотации. Оба варианта скачивают **один и тот же** JSON-документ (`warchi-notation-export` v2) — типы, компоненты, relations, правила и формы.

**Импорт из списка** — карточка рядом с «Создать нотацию»: выберите тот же JSON-файл экспорта, сервер создаёт **новую** нотацию у текущего пользователя. При успехе открывается редактор новой нотации. Если нотация с таким **именем и версией** уже есть, импорт вернёт **409** и ничего не сохранится.

**Импорт в редакторе** — из шапки редактора: выберите JSON-файл с полным описанием нотации для слияния с текущей нотацией.

## Редактор нотаций

Редактор нотаций — это визуальный инструмент для настройки внешнего вида и поведения элементов нотации.

### Компоненты нотации

Нотация состоит из следующих элементов:

- **Типы нод** — визуальные шаблоны для компонентов (прямоугольники, круги и т.д.)
- **Типы связей** — визуальные шаблоны для соединений (стрелки, линии)
- **Правила связей** — определяют, какие типы элементов могут быть соединены. Редактируются в свойствах компонента и через **Матрицу правил** в тулбаре редактора (клик по ячейке from→to).

### Настройка стилей

Для каждого типа ноды можно настроить:

- Форму (прямоугольник, эллипс, ромб и т.д.)
- Цвет заливки и обводки
- Шрифт и цвет текста
- Размеры по умолчанию
- Иконку

Для типов связей настраиваются:

- Тип линии (сплошная, пунктирная, точечная)
- Стиль стрелки (open, closed, diamond и т.д.)
- Цвет и толщина линии

### Формы узлов

В настройках стиля компонента можно выбрать форму узла:

- **Прямоугольник**
- **Прямоугольник с фаской**
- **Ромб**
- **Круг**
- **Усечённая пирамида** (trapezoid)
- **Параллелограмм** (slanted rectangle)
- **Кастомная форма**
- **Composite**

Практические рекомендации:

- для базовых сервисов и модулей чаще используют прямоугольник;
- ромб и трапеция подходят для специальных семантик (условия, агрегаторы, шлюзы);
- круг удобен для компактных ролей/событий;
- кастомная форма нужна, когда стандартных вариантов недостаточно и требуется фирменный контур.

Для **кастомной формы** контур берётся из каталога [Формы](/docs/shapes). Если при изменении размера узла углы или срезы «плывут», в редакторе формы включите **Фиксированные края (9-slice)** и задайте жёсткие зоны по направляющим — они не растягиваются при ресайзе. Подробнее — в [Формы → Фиксированные края](/docs/shapes).

Дополнительно:

- скругление (`R`) применяется для прямоугольных форм, где поддерживается радиус;
- у **прямоугольника с фаской** размер среза задаётся отдельно (`cornerCut`, в px), как радиус у скруглённого прямоугольника;
- после смены формы рекомендуется проверить отступы содержимого (`T/R/B/L`) и позицию метки.

### Composite UI-редактор

Для формы **Composite** в панели стиля доступен отдельный визуальный редактор:

- дерево `compositeContent` (узлы `container` / `text` / `icon` / `divider` / `shape`);
- инспектор свойств по типу выбранного узла;
- A5 form-builder для `stylePropertyBindings` с условными ветками;
- live preview;
- JSON-режим как расширенный fallback.

#### Как настраивать composite-компонент

1. Выберите форму **Composite** у компонента нотации.
2. Соберите структуру в дереве (`container` + дочерние `text`/`icon`/`shape` и т.д.).
3. Настройте свойства выбранного узла в инспекторе справа.
4. Добавьте A5-правила по схеме: **источник значения** -> **условие** -> **patch** (в целевой узел или во внешний контейнер).
5. Проверяйте изменения в live preview; JSON-режим используйте для точечных правок.

#### Что поддерживают биндинги

- **Текстовые узлы**: привязка к имени ноды и строковым пользовательским свойствам.
- **Иконки**: привязка к иконке компонента нотации (согласованное отображение в палитре и на диаграмме).
- **Style bindings (A5)**: условные патчи по свойствам компонента и свойствам типа ноды.

Поддерживаемые условия A5: `equals`, `contains`, `matchesRegex`, `isEmpty`, `isNotEmpty`, `is`, `range`, `lt`, `lte`, `gt`, `gte`.

### Элементы только для диаграммы в редакторе нотации

На превью-холсте нотации можно добавлять узлы и связи **только для диаграммы** (diagram-only):

- они **не** попадают в деревья компонентов и relations;
- хранятся в `editorDiagramLayer` внутри attrs нотации;
- экспортируются и импортируются вместе с данными нотации.

Так удобно собирать демонстрационные схемы и проверять стили без засорения каталога компонентов.

### Отступы содержимого, метки и иконки

В панели стиля узла есть три разных «отступа». Они вложены друг в друга и **не взаимозаменяемы**. Значения задаются в **пикселях**.

Для **отступа содержимого** любую сторону можно отметить как **пропорциональную (∝)**: число остаётся эталонным px при размере W×H стиля по умолчанию и при изменении размера узла пересчитывается. Неотмеченные стороны остаются фиксированными px.

Цепочка размещения:

```
фигура (внешние границы узла)
  └─ отступ содержимого (content inset, T/R/B/L)
        → контентная область
           ├─ иконка: зона по размещению → отступ иконки (одно число) → картинка
           └─ метка: вся контентная область → отступ метки (T/R/B/L) → текст
```

| Поле в стиле | Что ограничивает | Как задаётся |
|--------------|------------------|--------------|
| **Отступ содержимого** (`contentInset`) | Общий прямоугольник внутри фигуры, в котором рисуются метка и иконка | Стороны `T/R/B/L` |
| **Отступ метки** (`labelInset`) | Поля вокруг текста **внутри** контентной области (до выравнивания строк) | Стороны `T/R/B/L` |
| **Отступ иконки** (`iconInset`) | Зазор от края **зоны иконки** до самой картинки | Одно число (не по сторонам) |

Практические замечания:

- для «узких» силуэтов (например, актор с головой сверху) увеличьте **верхний отступ содержимого** и включите **∝** у этой стороны, чтобы текст оставался в «теле» при масштабировании фигуры;
- **отступ метки** удобен, когда нужно чуть отодвинуть глифы от краёв уже выбранной контентной области, не сдвигая иконку;
- **отступ иконки** не заменяет отступ содержимого: он действует только внутри зоны иконки;
- бейджи (например, интерактивные свойства) тоже опираются на контентную область и отдельных полей inset в стиле не имеют;
- режимы **Pair** / **All** в блоках `T/R/B/L` синхронизируют стороны парами или все сразу; подписи кнопок зависят от языка интерфейса.

Подробнее про позицию и выравнивание текста метки — в разделе [Выравнивание метки](#выравнивание-метки) ниже.

#### Подсказки сокращённых полей

В панели стилей для компактного отображения используются сокращения:

- `W/H/R` — ширина, высота, радиус;
- `PT/PB/PL/PR` — порты сверху/снизу/слева/справа;
- `T/R/B/L` — отступы сверху/справа/снизу/слева (для отступа содержимого и отступа метки).

При наведении курсора на поле отображается подсказка с расшифровкой.

### Пользовательские свойства

К типам нод и связей можно добавлять пользовательские свойства, которые будут доступны при редактировании модели. Свойства могут быть разных типов: текст, число, перечисление и др.

При создании свойства можно отметить его как **системное** — такие свойства используются для специального поведения в редакторе.

### Системное свойство `group`

Системное свойство `group` (тип `boolean`) нужно для включения логики **группирования компонентов** через семантику связей.

#### Зачем нужно

`group` позволяет описывать контейнерные отношения в модели (например, "сервис входит в подсистему") не только визуально, но и поведенчески:

- вложенные элементы можно перемещать вместе с контейнером;
- связи типа "группировка" не перегружают диаграмму лишними линиями;
- при переносе элемента внутрь контейнера система помогает быстро создать/подхватить правильную связь.

#### Для компонентов

Если у типа компонента есть системное поле `group=true`, компонент может работать как контейнер:

- при перетаскивании такого компонента вместе с ним перемещаются компоненты, полностью находящиеся внутри его области;
- компонент участвует в сценариях автогруппировки при drop внутрь другого компонента.

#### Для связей

Если у типа связи есть системное поле `group=true`, такая связь трактуется как связь группировки:

- когда `target` полностью внутри `source`, связь может быть скрыта на диаграмме (структурная связь сохраняется, но визуальный шум уменьшается); петли на себя (`source === target`) при этом не скрываются;
- при drop компонента внутрь другого, если допустима связь с `group=true`, редактор предлагает использовать существующую связь или создать новую;
- если вариантов связи несколько, показывается выбор типа связи.

#### Настройка

1. Создайте пользовательское свойство с именем `group`.
2. Установите тип `boolean`.
3. Обычно задайте значение по умолчанию `true` (если тип всегда участвует в группировке).
4. Включите флажок **Сист.** (системное свойство).
5. Настройте это поле для нужных типов:
   - для **типов компонентов** — чтобы разрешить контейнерное поведение;
   - для **типов связей** — чтобы пометить связь как группирующую.

### Интерактивные свойства на диаграмме

Для свойств **компонентов** можно включить опцию **«Интерактивное на диаграмме»**. Тогда у узлов с заполненным значением этого свойства на диаграмме в левом верхнем углу отображается иконка-кнопка; по клику выполняется действие в зависимости от выбранного типа. Для любого интерактивного свойства (URL, Диаграмма, Документ) тип свойства должен быть **«строка»**; при выборе типа действия тип при необходимости подставляется автоматически.

#### Типы действий и что вводить в свойство

| Тип действия | Что ввести в значение свойства | Пример | Поведение по клику |
|--------------|--------------------------------|--------|---------------------|
| **URL** | Адрес веб-страницы | `https://wiki.example.com/ServiceA` | Открывается в новой вкладке браузера |
| **Диаграмма** | Идентификатор (UUID) диаграммы в текущей модели | `a1b2c3d4-e5f6-7890-abcd-ef1234567890` | Редактор переключается на эту диаграмму (выбор в дереве слева) |
| **Документ** | Идентификатор (UUID) файла документа | `f0e1d2c3-b4a5-9876-5432-10fedcba0987` | Открывается окно просмотра/редактирования документа с этим файлом |

#### Как заполнять в редакторе модели

В редакторе модели для типа **Диаграмма** и **Документ** доступен выпадающий список вместо ввода UUID вручную: выбирается диаграмма по имени и версии или документ из уже привязанных в модели (к узлам или диаграммам). Для типа **Документ** есть кнопка **«Новый документ»**: создаётся пустой документ в хранилище, его идентификатор подставляется в свойство. Для **URL** вводится адрес в текстовое поле; при настройке свойства в нотации можно задать поле «Regex» для проверки формата ссылки (для типа URL подставляется типовой шаблон).

#### Как получить идентификаторы (при необходимости вручную)

- **Диаграмма**: каждая диаграмма в дереве модели имеет уникальный UUID. Идентификатор можно скопировать при перетаскивании диаграммы (в буфер помещается текст вида `diagram:<uuid>` — используйте часть после `diagram:`) или получить из экспорта/API модели.
- **Документ**: при привязке документа к узлу или к диаграмме система сохраняет идентификатор файла. Этот же идентификатор нужно указать в интерактивном свойстве типа «Документ», если вы хотите открывать тот же файл по клику на бейдж. Идентификатор возвращается при сохранении документа или при выборе существующего файла в редакторе модели.

#### Настройка в редакторе нотации

1. Откройте компонент нотации и нужное пользовательское свойство.
2. Включите **«Интерактивное на диаграмме»**.
3. Выберите **тип действия**: URL, Диаграмма или Документ.
4. Выберите **иконку** для кнопки на диаграмме (link, open_in_new, description, article и др.).
5. Сохраните нотацию.

В редакторе модели при заполнении этого свойства у узла на диаграмме появится соответствующая иконка; по клику выполнится выбранное действие.

### Шаблоны меток

Для компонентов нотации можно задать шаблон **составной метки**: какой текст показывается на узле на диаграмме. В шаблон входят имя ноды, поля **типа ноды** и поля **компонента нотации**; значения редактируются в [редакторе модели](/docs/models) (см. панель свойств ноды).

#### Синтаксис

- `${name}` — **имя ноды** на диаграмме (зарезервировано; это не пользовательское поле компонента)
- `#{ключ}` — значение **пользовательского свойства типа ноды** (ключ как в каталоге [Типы](/docs/types))
- `${ключ}` — значение **пользовательского свойства компонента нотации** (ключ из секции свойств компонента ниже)

**Важно:** символ **`#`** относится только к полям типа ноды; **`$`** — к имени ноды (`name`) или к полям компонента.

Если шаблон не задан, отображается имя ноды (поведение по умолчанию).

#### Примеры

| Шаблон | Результат |
|--------|-----------|
| `${name}` | только имя ноды, например `API Gateway` |
| `${name} · #{code} · ${status}` | имя, код из типа ноды, статус из компонента |
| `${name} [${status}]` | имя и значение свойства **компонента** `status`, например `API Gateway [active]` |
| `${protocol}://${name}:${port}` | если `protocol` и `port` заданы у **компонента** — составной текст с именем ноды |
| `${name}\n#{description}` | имя на первой строке, описание из **типа** — на второй |

#### Перенос строки

Для многострочных меток используйте `\n` в шаблоне. Например, `${name}\n${status}` выведет имя на первой строке, а `status` из **компонента** — на второй.

#### Где настроить

Шаблон метки можно задать в двух местах:

- **Панель стиля** — поле «Шаблон» в секции «Метка» при выбранном компоненте на диаграмме
- **Панель свойств** — секция «Составная метка» с полем ввода и предпросмотром результата

#### Поведение

- Если свойство из шаблона не найдено — плейсхолдер заменяется на пустую строку
- При двойном клике на узел для переименования отображается только имя ноды, а не результат шаблона
- В **редакторе модели** значения берутся из панели свойств ноды: блоки **«Свойства типа ноды»** и **«Свойства компонента нотации»**; при отсутствии — из значений по умолчанию схем типа и нотации
- В **превью** в редакторе нотации подставляются значения по умолчанию из схем; для полей типа ноды используются дефолты типа (как в интерфейсе)
- **Миграция:** раньше значения полей типа ноды могли указываться через `${ключ}`; теперь для типа ноды используйте **`#{ключ}`**, а `${ключ}` оставьте для полей **компонента**
- Шаблоны поддерживаются только для узлов (не для связей)

### Выравнивание метки

Метка узла имеет две независимые настройки расположения:

- **Позиция** — к какому краю фигуры прижата метка (авто, центр, сверху, снизу, слева, справа)
- **Выравнивание** — как строки текста выровнены внутри метки (по центру, по левому краю, по правому краю). Актуально для многострочных меток.

## Версионирование нотаций

Нотации, как и модели, поддерживают семантическое версионирование. При создании новой версии нотации копируются все типы и стили из предыдущей версии.
