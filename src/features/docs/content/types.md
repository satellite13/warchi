# Типы нод и связей

Типы — это глобальные сущности, определяющие структуру элементов архитектурных моделей. Тип задаёт **название** элемента и набор **пользовательских свойств**. Визуальное оформление (форма, цвет, иконка) настраивается отдельно в компонентах нотации, привязанных к типу.

Управление типами осуществляется через раздел **Типы** в навигационном меню.

## Типы нод

Типы нод описывают компоненты архитектуры — сервисы, модули, базы данных, интерфейсы и другие элементы.

Тип ноды задаёт **семантику компонента** (что это за сущность), а внешний вид (форма, цвет, иконка, подписи) настраивается в нотации через component-компонент.

### Свойства типа ноды

| Свойство | Описание |
|----------|----------|
| Название | Уникальное имя типа |
| Иконка (`icon`) | SVG-иконка типа. Используется в палитре и списках для визуального различения типов |
| Директория по умолчанию (`defaultDirectoryPath`) | Путь каталога, который подставляется как значение по умолчанию для размещения/структурирования компонентов этого типа |

### Создание типа ноды

1. Перейдите в раздел **Типы**
2. В панели типов нод нажмите **«Добавить»**
3. Введите название типа
4. (Опционально) выберите иконку типа
5. (Опционально) укажите директорию по умолчанию
6. Сохраните изменения

### Где используется тип ноды

После создания тип ноды обычно используется в двух местах:

1. **В нотации** — создаётся component-компонент, привязанный к типу ноды, где задаются стиль и поведение на диаграмме.
2. **В модели** — пользователи создают экземпляры компонентов этого типа и заполняют пользовательские свойства.

Дополнительно:

- поле `icon` помогает быстрее находить нужные типы в палитре и списках;
- поле `defaultDirectoryPath` задаёт рекомендуемую структуру хранения для новых экземпляров компонента.

Если тип ноды не связан с компонентом в нотации, его нельзя полноценно использовать на диаграммах.

### Удаление типа ноды

Тип можно удалить через контекстное меню или кнопку удаления. Перед удалением убедитесь, что тип не используется в нотациях и моделях.

### Изменение типа ноды

- Переименование типа ноды влияет на все места использования (нотации, модели, правила связей).
- При добавлении новых пользовательских свойств учитывайте влияние на существующие экземпляры в моделях (особенно для обязательных полей).

## Типы связей

Типы связей описывают отношения между компонентами — зависимости, потоки данных, наследование и т.д.

Тип связи отвечает за **семантику** связи (что означает связь), а визуальное представление задаётся в нотации через relation-компонент (линия, маркеры, подписи, цвета).

### Свойства типа связи

| Свойство | Описание |
|----------|----------|
| Название | Уникальное имя типа связи |

> В проектах с группировкой обычно используется системное поле `group` (тип `boolean`) у типа связи, чтобы пометить её как группирующую. Это влияет на поведение редактора диаграмм (автолинки в группах, скрытие структурных связей в контейнерах).

### Создание типа связи

1. Перейдите в раздел **Типы**
2. В панели типов связей нажмите **«Добавить»**
3. Введите название типа связи
4. Сохраните изменения

### Где используется тип связи

После создания тип связи обычно настраивается в двух местах:

1. **В нотации** — создаётся relation-компонент, который привязывается к этому типу связи и задаёт его визуальный стиль.
2. **В правилах связей** — добавляются ограничения source/target, определяющие, какие типы компонентов могут соединяться этой связью.

Без правил связей в нотации связь может быть недоступна при интерактивном соединении на диаграмме.

### Изменение и удаление типа связи

- Переименование типа связи влияет на все места, где он используется (нотация, правила, модели).
- Перед удалением убедитесь, что тип не используется в нотациях и существующих моделях, иначе будут недоступны связанные сценарии редактирования.

## Пользовательские свойства

К типам нод и связей можно добавлять пользовательские свойства. Эти свойства будут доступны при редактировании экземпляров в модели.

Поддерживаемые типы свойств:

- **Текст** — строковое значение
- **Число** — числовое значение
- **Перечисление (enum)** — выбор из заданного списка значений

Для каждого свойства можно указать:

- Имя свойства
- Тип данных
- Значение по умолчанию
- Обязательность заполнения
- Системный флаг (**Сист.**) для специальных сценариев редактора

> При добавлении нового обязательного свойства с дефолтным значением, существующие экземпляры в моделях автоматически получат значение по умолчанию при следующем открытии модели.

Системные свойства применяются для специальной логики редактора. Наиболее частый пример — `group` (`boolean`), который используется в сценариях группировки компонентов и группирующих связей.

## Правила связей

Правила связей определяют, какие типы нод могут быть соединены определёнными типами связей. Это позволяет обеспечить корректность архитектурных моделей.

### Настройка правил

Для каждого правила указываются:

- **Связь** — тип связи (relation), к которому применяется правило
- **Источник** — допустимый тип компонента-источника
- **Приёмник** — допустимый тип компонента-приёмника

## Связь типов и нотаций

Типы — глобальные сущности, доступные во всех нотациях. В редакторе нотаций типы используются для создания **компонентов** и **связей** нотации. Компонент нотации привязывается к типу и добавляет визуальное оформление: форму, цвет, иконку, стиль линии и другие параметры отображения на диаграмме.
